# 知识点映射表 — 证明“这是数据结构作业”

> 自选题最大的风险不是做得差，而是老师看不出它算不算数据结构作业。
> 本表放在报告第 3 章，答辩时作为**唯一能证明“我在做数据结构、不是在写游戏”**的材料。

| 课程知识点 | 项目中的对应模块 | 源码位置 | 掌握程度佐证 |
|---|---|---|---|
| 图（邻接表/邻接矩阵） | 网格图建模：每格一个顶点，4/8 邻接为边 | `include/GridGraph.h`、`types.h` 中 `Grid[y*cols+x]` | 能画出"格子—顶点—边"的映射，解释为何一维数组是稠密邻接矩阵 |
| 优先队列（二叉堆） | open list：每轮取 f 最小节点 | `include/MinHeap.h` 的 `BinaryHeap::push/pop` | **自己实现**，上滤/下滤 O(log n)；能现场讲出下滤过程；能解释 tie-break(f 同按 h) |
| 哈希表 / 集合 | closed set 判重，避免重复扩展 | `PathFinder.cpp` 中 `closed: vector<uint8_t>` | 说明"顶点已连续编号，直接寻址数组是 O(1) 访问，等价于最扁的哈希集合" |
| 队列（FIFO） | BFS 对照组 | `PathFinder.cpp` 中 `std::deque<int> queue` | 能对比"队列先进先出 → 无权图最短路"与"堆按优先级 → 带权/启发搜索" |
| 排序 / 选择 | 每轮取 f 最小：堆 vs 全排序的复杂度差 | `MinHeap.h` 的 `BinaryHeap` 与 `LinearOpenList` | 规模实验实测 512² 下 6.55×；能推导 O((V+E)logV) vs O(V²) |
| 递归 | 迷宫生成（递归分割） | `Terrain.cpp` 的 `divide()` | 能讲清"递归地把矩形一分为二并留缺口，天然保证连通"及连通性兜底 |
| 回溯 | 路径还原 | `PathFinder.cpp` 中 `cameFrom` 前驱数组 | 找到终点后沿前驱回溯，O(路径长) |

## 答辩时如何主动使用这张表

1. 开场 1 分钟内就展示本表，明确"我的项目每一部分都落在课程大纲内"。
2. 老师问"这和游戏/AI 有什么区别"时，直接指本表："核心是优先队列与图搜索的实现，可视化只是验证手段。"
3. 老师问"难点在哪"时，回答堆的 tie-break 与 lazy-deletion 的取舍，以及迷宫连通性兜底。
4. 强调未使用 `STL priority_queue` / `heapq`：自己实现才能控制比较逻辑、才能讲清复杂度来源。
